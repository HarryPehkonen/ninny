# Ninny v1.0.0 — the artifact claim, and the horizon question

**Goal:** make Ninny guarantee the *artifact* — a test seen to fail, the same test seen to pass, a suite
provably unedited since the red, an implementation graded by an external corpus — and then settle, with
one honest experiment, whether test-first buys anything beyond that.

**Where we are (measured, 63 arms):**

| | |
|---|---|
| acceptance | 100% everywhere except `bits` (0/3) |
| red-first | 13% (`off`) → 100% (`enforce`, `split`) — fully controlled |
| the 3 failures | all one mechanism: correct code, suite never seen green |
| shipped-suite teeth | 15/15 and 15/15 mutants killed in **every** mode, `off` included |
| horizon | every task sits inside METR's ~100%-success band (<4 human-minutes) |

External grounding: SWT-Bench (NeurIPS 2024) shows the artifact is worth ~2x precision — a test that was
red and then green is real evidence about the code. No harness we found grades the *order* of writes.
So: enforce ordering only insofar as it guarantees the artifact, and claim the artifact, not the pedagogy.

**What this plan will NOT touch:** no new tools, no new dependencies (stdlib stands), no mode renames or
semantic changes (`off`/`request`/`enforce`/`reverse`/`split` stay comparable), no model shopping, no new
traps on short tasks (that band is saturated), no version bump until Harri approves.

## Phase 1 — Close the handback (highest payoff: the corpus now fails correct code)

Evidence: `bits` 0/3, all `ok the acceptance corpus builds and passes` + `FAIL the submission's own tests
do not pass`. Last observed run at steps 8 / 29 / 15, then 21 / 11 / 14 steps of work and a handback.

### Task 1.1 — Record the observation gap (5 min)
- Modify `ninny/tdd.py`: track `last_run_step`, `last_src_step`; expose `suite_stale` (true when no run
  happened after the most recent source write).
- Modify `as_dict()` so `result.json` carries both steps and `suite_stale_at_submit`.
- Test: `tests/test_phase_vocabulary.py` — record shape only.

### Task 1.2 — Close it by running it, not by asking (10 min)
- In the submit path (`ninny/tdd.py`, where `submit on a red tree` is refused today): if the suite is
  stale, **run it once**, record that the harness ran it, and refuse the submit once with a message
  naming the last run step. Second attempt passes, refusal recorded — same shape as the existing nudge,
  and the same termination rule Claude Code's docs demand for a blocking Stop hook.
- Tests: `tests/test_suite_seal.py` — (a) stale + green → refused once, allowed, `suite_stale_at_submit`
  false after the harness run; (b) stale + red → the red path wins; (c) fresh + green → untouched.

### Task 1.3 — One oracle standard, declared (20 min)
- `bits` gates acceptance on the submitted suite passing; `spans` accepts a red handback (3/3). Same
  protocol, two standards ⇒ the acceptance column is not comparable across tasks, and `bits`' gate is
  one the seal forbids meeting (a wrong sealed test has no write path).
- Add `oracle_gate = "implementation"` (default) to every `task.toml`; `bits` declares the same, and its
  oracle **records** the shipped suite's colour (`shipped_suite: green|red`) instead of failing on it.
- Update `docs/AUTHORING-TASKS.md` and add a check in `scripts/verify-tasks.sh` that each task declares
  `oracle_gate`, so the standard cannot drift silently again.

### Task 1.4 — Prove it on the arms that failed (15 min, ~$0.08)
- Re-run `bits` enforce ×3 (`AB_TASKS=bits AB_STATES=enforce AB_ARMS=3`), score, and confirm 3/3 accepted
  with `suite_stale_at_submit` false — i.e. the harness closed the gap on exactly the arms that exposed it.
- Commit + push (`git add` explicit paths, gate green).

**Cost:** ~1 h. **Verification:** unit tests + 3 arms + the record.

## Phase 2 — Speak the protocol, shrink the prompt (the two-message script)

Evidence: the testing block is 38 of 109 lines; 43 lines are the task's own spec, 18 the tool manual, and
the growth is one paragraph per measured misbehaviour. A preamble describes a state machine; the harness
is the only party that knows when round one ended.

### Task 2.1 — Inject round two (20 min)
- In `ninny/agent.py`, on the red transition (`seal_step`), append one harness message: implement the spec,
  test files are read-only from here, a sealed test that is wrong is reported not edited, never hand back
  a suite you have not run since your last change.
- Tests: `tests/test_split_mode.py` — the message appears exactly once, at the red, and not in `off`.

### Task 2.2 — Delete the preamble it replaces (20 min)
- `ninny/prompt.py`: `TDD_BLOCKS["split"]` from ~29 lines to ~10 (the ask + the exit-code rule). Move the
  seal, exit-2 and red-handback explanations into the refusal messages that trigger them.
- Test: assert the block is ≤ 12 lines (it cannot grow back silently) and each refusal text exists.

### Task 2.3 — Measure (20 min, ~$0.10)
- `split` on `bits` ×3 (the hardest task) against the 4 existing split arms: prompt lines, steps, cost,
  red-first, seal, acceptance, teeth.

**Cost:** ~1 h + $0.10. **Open call:** split only (recommended) or also `enforce`.

## Phase 3 — The horizon task (the only path to an outcome claim)

### Task 3.1 — Tag the corpus (15 min)
- `human_minutes` in every `task.toml`; today all ten are under ~45 minutes.

### Task 3.2 — Author one long task: RFC 6902 JSON Patch + RFC 7386 Merge Patch (~3 h)
- Multi-file (`parse`, `apply`, `errors`, `cli`), ordered operations (`add`/`remove`/`replace`/`move`/
  `copy`/`test`), JSON Pointer composition (reuses `jsonptr`), atomic failure semantics, official
  example corpora from both RFCs. Expect ~2–4 human hours, 40–100 agent steps, resumable across steps.
- Path: `tasks/jsonpatch/{SPEC.md,task.toml,tree/,fixed/,sabotage/,oracle/}`; add `sabotage_target`.

### Task 3.3 — Pre-flight with the existing recipe (~45 min, no model money)
- Answer key passes the corpus; stub fails it; 5 sabotages each pass the RFC's own examples and fail the
  corpus; `ninny verify-task` VERIFIED (3 controls, incl. the planted-test probe).

### Task 3.4 — The experiment (~$0.40)
- `off` ×3, `enforce` ×3 (Phase 1 rules on), `split` ×3. Report acceptance, red-first,
  `suite_stale_at_submit`, mutant-kill, steps, cost — and, the only number that has never moved:
  **submitted-and-wrong**.

**Cost:** ~4 h + $0.40. Negative result is a result: if 3/3 still accepted, the finding is that this model
class saturates at 100 steps too, and the horizon has to grow again.

## Open calls (mine marked)

1. **Oracle standard** — record the shipped suite's colour, do not gate acceptance on it (**recommended**:
   a gate the seal forbids meeting is a trap) vs keep `bits`' gate and add a recorded repair path.
2. **Long task** — RFC 6902 + 7386 JSON Patch (**recommended**: official corpora, real composition, reuses
   `jsonptr`) vs a from-scratch multi-file app.
3. **Phase 2 scope** — `split` only (**recommended**, it is the two-round mode) vs `split` + `enforce`.

## Risks

- The long task is the largest single authoring cost; keep its grading official-corpus-driven, because our
  own oracles have needed an answer-key control to catch 9 of 10 bugs.
- A 3/3 acceptance result on the long task is the likely outcome and is not a failure — it is the answer to
  "does test-first buy anything" at that horizon.
- Phase 1.2 must refuse **once** and record it: a hard block would strand runs, which is the same trap the
  exit-2 door was.
